# Localization String Inventory — L0 Artifact

Generated by `extract-strings.mjs` (heuristic scan) on 2026-10-02. Source: every non-test `.tsx` under `apps/web/src` that does **not** yet use `tr()`/`useLocale`. The appendix at the bottom holds the full extraction; this header is the working contract for batches L2–L7.

## Purpose

Per-batch worklist. Every candidate in the appendix must end a batch as one of:

1. **Catalog key** — `en` value byte-identical to the current literal, `am`/`ar` translated in the same change.
2. **Waived with reason** — code-like strings, class names, data-driven values, or intentional English (see waivers below).
3. **Moved to `status` module** — enum-derived displays (order/payment/shift/KDS/day-close/inventory states).

## Invariants (from the approved plan)

1. **`en` values are byte-identical to the current copy** — the 20 English-asserting unit test files and every Playwright spec stay green with zero test edits. A test failure means the `en` value is wrong, not the test.
2. **All three locales updated in the same change** — `parity.test.ts` enforces key-set, non-empty, and placeholder parity per namespace.
3. **Placeholders identical across locales** — `{name}` style, same set in en/am/ar (parity-enforced).
4. **Count-bearing strings use `PluralForms`** (`{ one, other }` + `{count}` variable) wherever Amharic/Arabic grammar needs it.
5. **Template literals convert to placeholders**: `` `${x} items` `` → `'{x} items'` + `tr(key, { x })`.
6. **Server/DB/API strings pass through untranslated**; only known client-handled error codes map to `validation.*` keys (documented limitation in `LOCALIZATION.md`).

## Key naming conventions

- `camelCase`, readable phrases matching existing style (`saveProfile`, `noBranchesFound`, `navOrders`).
- Keys are unique within a module; shared cross-feature concepts belong in `status` (never duplicated per feature).
- `common (primitive-internal)` = aria/copy inside `ui/*` primitives. Primitives stay prop-based — only add `common.*` keys for strings the primitive owns itself (e.g., an internal close-button label).
- `feedback` module = generic loading/empty/error/offline/permission state copy shared across features; feature-specific empty-state text stays in the feature module.
- Reserved (not yet created): `expo` — unblocks with the `/expo` crash fix.

## Extraction caveats

- Heuristic scan: ~1,130 raw entries **including duplicates and known noise** (e.g., className template literals containing `${}` — see `dashboard.tsx:184`). Unique key count will be materially lower.
- Expected false negatives: multi-line JSX text nodes, strings assembled via `.join()`/`.map()`, concatenated literals. **Every batch must finish with a leftover-literal grep plus a human read of the diff.**
- `enum` kind entries (ternaries, `.replace('_',' ')`, `.toUpperCase()`) are the hidden majority in tables — they map to the `status` module in L1 wherever the same label appears in two or more features.

